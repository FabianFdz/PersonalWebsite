# TICKET-001 — Generate canonical integrity metadata from artifact bytes

## User value

Delivery agents can prepare integrity-bearing handoffs without inventing, calculating, or manually transcribing derived checksum data.

## Description

Provide a deterministic repository operation that populates or updates checksum-derived handoff evidence from the bytes of selected artifact files. The operation must define canonical ordering, serialization, encoding, and line-ending behavior and must update outputs atomically.

## Dependencies

None.

## Acceptance criteria

1. A repository operation can populate or update all checksum-derived fields for selected handoff artifacts by reading their real bytes; the caller never supplies a digest value.
2. Identical ordered inputs and file bytes produce byte-identical output across repeated runs, including stable ordering, serialization, encoding, and line endings.
3. Changing one artifact byte produces a deterministic checksum change or mismatch.
4. An unavailable, ambiguous, or failed integrity operation leaves the existing handoff and derived evidence unchanged and reports an actionable recovery step; no manual or visual fallback is accepted.
5. Automated tests prove repeatability, canonical output, one-byte sensitivity, and failure atomicity.

## Validation notes

- Exercise repeated generation from unchanged fixtures and compare the generated bytes.
- Mutate one fixture byte and verify the result changes deterministically.
- Force a generation failure and verify no partial output replaces the prior file.
- Run `pnpm run harness:validate`, `pnpm test`, and `pnpm run lint`.

## Estimated complexity

Medium.
